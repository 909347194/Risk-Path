# 基于风险时空异质性的城市低空无人机航路规划实验工程指导

本文档用于指导 `methods/spatiotemporal_heterogeneity` 下的实验工程建设。目标不是把所有模块一次性写满，而是围绕论文 `paper/manuscript1/02_tpr_cost_models.tex` 与 `paper/manuscript1/03_comprehensive_risk_formulation.tex` 中的模型，形成一条可复现、可解释、能支撑论文实验章节的工程闭环。

核心问题可以概括为一句话：

> 在城市低空环境中，路径规划不应只最短或只静态避障，而应根据时间、空间、气象、人口、土地利用和建筑形态的动态风险成本，选择综合风险更低的 4D 航路。

---

## 1. 实验要证明什么

论文实验不要先追求“大而全”，而要清楚证明以下几个主张。

### 1.1 动态坠机概率不是常数

对比常数 `P_crash` 与动态 `P_crash(x,y,z,t)`：

- 风速越接近抗风极限，局部坠机概率应明显上升。
- 降雨越强，坠机概率应按二次项放大。
- 高楼密集、天空可视因子低、离建筑近的城市峡谷区域，坠机概率应高于开阔区域。

对应论文模型：

- `P_crash = 1 - exp(-lambda_base * Phi * delta_t)`
- `Phi = f_wind * f_rain * f_obs`

实验产物应包括 `P_crash` 的空间切片、时间切片和边界条件检查。

### 1.2 风险成本具有时空异质性

同一个起终点，在早高峰、白天、夜间可能应走不同航路：

- 早晚高峰应避开交通主干道和高人口密度区。
- 夜间应更强地避开住宅区噪声敏感区域。
- 白天应更强地避开学校、医院等敏感区域。

对应论文模型：

- 动态人口/车辆密度：`rho(i,t)`
- 噪声社会成本：`Cost_noise(i,z,t)`
- 土地利用与时间惩罚组成 S-T sensitivity matrix。

### 1.3 概率风险和确定性噪声必须解耦

实验中要坚持一个关键因果关系：

- 人员伤亡和财产损失是坠机后的期望后果，所以要乘以 `P_crash`。
- 噪声是正常飞行必然产生的社会滋扰，所以不能乘以 `P_crash`。

论文综合代价应保持：

```text
J_total = w_ops * C_ops
        + w_fatal * (P_crash * c_fatal)
        + w_prop  * (P_crash * c_property)
        + w_noise * C_noise
```

这点是论文理论贡献之一，不要在 `tensor_builder` 中把所有张量简单加权后就结束。

### 1.4 多目标权重会改变路径形态

`configs/cost_weight.yaml` 已经定义了四类场景：

- `default`：均衡模式。
- `emergency`：急救模式，效率优先。
- `quiet_night`：深夜静音模式，噪声优先。
- `strict_safety`：绝对安全优先，伤亡和财产风险优先。

实验需要展示不同权重下路径长度、风险暴露、噪声成本之间的权衡。

## 4. 最小可发表实验目标

建议先完成一个 Minimum Publishable Experiment，简称 MPE。它不需要真实城市所有数据齐全，但必须能证明论文机制。

### 4.1 微观机制验证场景

使用 `env_config.yaml` 中的 `micro_validation`：

- 空间范围：`400m x 400m x 120m`
- 网格分辨率：`10m x 10m x 10m`
- 网格维度：`40 x 40 x 12`
- 时间维度：建议先用 24 个整点小时，降低调试复杂度。
- 起点终点：建议固定为对角线方向，例如西南低空入口到东北低空出口。

此场景用于证明：

- 建筑硬避障有效。
- 动态风险张量能影响路径。
- 不同时间和权重会改变路径选择。

### 4.2 宏观城市案例场景

使用 `env_config.yaml` 中的 `macro_city`：

- 空间范围：`5000m x 5000m x 120m`
- 网格分辨率：`50m x 50m x 10m`
- 网格维度：`100 x 100 x 12`
- 时间维度：建议采用全局 `time.total_slices = 96`，即 15 分钟一个时间片。

此场景用于论文案例研究：

- 展示城市级人口潮汐和噪声敏感区对航路的影响。
- 展示算法在更大网格上的运行效率。
- 生成论文主图和主表。

## 5. 张量数据契约

所有模块要围绕统一张量契约工作。建议采用以下约定。

### 5.1 坐标与维度

默认张量轴顺序：

```text
(x, y, z, t)
```

其中：

- `x, y`：水平网格索引。
- `z`：高度层索引。
- `t`：离散时间片索引。

如果某个变量本质上没有高度或时间维度，也应在导出前广播到统一形状，或明确保存为低维底图并在 `tensor_builder` 中广播。

### 5.2 核心张量清单

| 名称 | 推荐形状 | 类型 | 含义 |
|---|---:|---|---|
| `obstacle_mask` | `(X,Y,Z)` | bool | 建筑硬约束，True 表示不可飞 |
| `p_crash` | `(X,Y,Z,T)` | float | 动态坠机概率 |
| `population_density` | `(X,Y,T)` 或 `(X,Y,Z,T)` | float | 动态人口密度 |
| `vehicle_density` | `(X,Y,T)` 或 `(X,Y,Z,T)` | float | 动态车辆密度 |
| `fatal_cost` | `(X,Y,Z,T)` | float | 不含 `P_crash` 的伤亡后果成本 |
| `property_cost` | `(X,Y,Z)` 或 `(X,Y,Z,T)` | float | 不含 `P_crash` 的财产后果成本 |
| `noise_cost` | `(X,Y,Z,T)` | float | 不乘 `P_crash` 的确定性噪声成本 |
| `ops_cost` | edge-level | float | 航段飞行时间或距离成本 |
| `total_cost` | edge-level 或 `(X,Y,Z,T)` | float | 按论文公式合成后的综合代价 |

### 5.3 硬约束与软成本分离

`obstacle_mask` 不应只作为一个很大的成本值处理。建筑占据体素应作为硬约束直接剪枝：

```text
v in NoGo iff z <= building_height(x,y) + safety_margin
```

原因：

- 硬约束能保证路径不会穿楼。
- 高成本惩罚可能仍被搜索算法在极端权重下选中。
- 论文中禁飞区约束是可行性约束，不是软目标。

### 5.4 时间单位

`lambda_base` 在论文和配置中应理解为“每小时失效率”。因此：

- 若时间片是 15 分钟，则 `delta_t = 0.25 h`。
- 若边的飞行时间是 10 秒，则 `delta_t = 10 / 3600 h`。

不要把秒直接传入 `P_crash = 1 - exp(-lambda_base * Phi * delta_t)`，否则风险会被放大 3600 倍。

### 5.5 归一化原则

归一化是实验可信度的关键。

建议：

- 每个成本分量先保留物理单位版本。
- 再生成归一化版本用于规划。
- 归一化统计量要保存，例如 `min/max/percentile`。
- 重尾分布如人口、财产损失，可先 `log1p` 再 min-max。
- 不要按单条路径归一化，否则不同路径不可比较。
- 不要按每个时间片单独归一化，否则早晚风险强弱会被抹平。

## 6. 模块职责建议

### 6.1 `data_provision`

职责是把原始数据变成统一网格底图。

建议产物：

- 建筑高度栅格：`building_height[x,y]`
- 建筑占地/截面积：`building_area[x,y]`
- 土地利用类别：`landuse[x,y]`
- POI 类别与坐标：`poi_table`
- 静态人口底图：`base_population[x,y]`
- 道路等级/基础车流底图：`base_vehicle[x,y]`
- 风雨数据：`wind[x,y,z,t]`、`rain[x,y,t]`

真实数据未准备好时，可以先使用 `data/04_mock` 构造合成数据，但论文中必须明确说明“机制验证场景”为合成或半合成。

### 6.2 `tensor_engine`

职责是将底图和配置转为风险成本张量。

建议模块边界：

- `static_obstacle.py`：生成 `obstacle_mask`、建筑高度相关底图、财产成本底图。
- `dynamic_p_crash.py`：生成 `p_crash`，同时输出 `f_wind`、`f_rain`、`f_obs` 便于消融。
- `dynamic_population.py`：生成 `population_density` 和 `vehicle_density`。
- `dynamic_noise.py`：生成 `noise_cost`，包含高度衰减、土地利用敏感度和时间惩罚查表。
- `tensor_builder.py`：按论文公式组合 `ops/fatal/property/noise`，不是普通张量求和器。

### 6.3 `algorithms`

建议先完成一个可靠版本，而不是一开始就实现完整 EDA。

优先级：

1. `cost_astar.py`：时间推进的 3D/4D Cost-A*。
2. `baseline_astar.py`：只考虑距离和障碍物的最短路径 A*。
3. `static_risk_astar.py`：使用静态平均风险图的基线。
4. `eda_macro.py` 和 `kmeans_corridor.py`：作为加速或全局引导模块，后置实现。

### 6.4 `eval_and_vis` 或 `visualization`

职责是把路径结果转成论文可用证据。

建议产物：

- `metrics.csv`：每条路径的分项成本。
- `path_nodes.csv`：路径节点、时间、高度和局部成本。
- 2D 风险热力图。
- 3D 城市航路图。
- 时间切片对比图。
- 权重敏感性/Pareto 图。

## 7. 推荐实验组设计

### E0：模型边界条件验证

目的：证明公式实现与论文表格一致。

检查项：

- `f_wind` 在 `v/V_limit = 0, 0.5, 0.8, 1.0, >1.0` 时是否符合预期。
- `f_rain` 在 `I = 0, 5, 15, 30, 50 mm/h` 时是否符合预期。
- `f_obs` 在 `R_canyon = 0, 0.2, 0.5, 0.8, 1.0` 时是否符合预期。
- `P_crash` 是否始终在 `[0,1]`。
- `P_crash` 是否没有 NaN。

论文用途：支撑模型正确性和边界合理性。

### E1：微观路径规划机制验证

目的：证明本文方法不是单纯绕障，而是绕开风险热点。

对比方法：

- `Shortest-A*`：只考虑距离和障碍。
- `StaticRisk-A*`：使用静态平均风险。
- `TimeAwareRisk-A*`：使用时间相关风险，但不使用噪声。
- `FullRisk-A*`：使用完整综合代价。

期望现象：

- 最短路径可能贴近建筑或穿过高人口区。
- 静态风险路径能绕开平均高风险区，但不能响应昼夜变化。
- 完整方法在夜间更倾向避开住宅区，在白天更倾向避开学校/医院。

论文用途：主路径对比图、分项成本表。

### E2：同一起终点的时段对比

目的：证明“时间”改变最优路径。

建议测试时间：

- 08:00 早高峰。
- 12:00 白天平峰。
- 18:00 晚高峰。
- 22:00 夜间安静时段。

固定：

- 起点终点不变。
- 权重使用 `default` 或 `quiet_night`。

输出：

- 四条路径叠加图。
- 每条路径的 `fatal/property/noise/ops/total` 分项表。
- 路径经过住宅、学校、主干道上方的暴露时间。

论文用途：证明时空异质性是必要的。

### E3：权重场景对比

目的：证明多目标权重能表达不同应用需求。

使用 `cost_weight.yaml`：

- `default`
- `emergency`
- `quiet_night`
- `strict_safety`

固定同一 OD 和同一出发时间。

期望现象：

- `emergency` 路径更短，但风险或噪声可能更高。
- `quiet_night` 路径更绕，明显避开住宅区。
- `strict_safety` 路径更保守，避开高人口、高建筑风险和高 `P_crash` 区。

论文用途：权重敏感性图和 Pareto 分析。

### E4：消融实验

目的：证明每个风险分量都有贡献。

建议消融组：

- `Full`：完整模型。
- `NoWindRain`：去掉风雨动态，仅保留建筑因子。
- `NoUrbanCanyon`：去掉建筑峡谷风险，仅保留气象。
- `ConstantPcrash`：把 `P_crash` 设为常数。
- `StaticPopulation`：人口密度不随时间变化。
- `NoNoiseST`：噪声只保留高度衰减，不使用土地利用和时间惩罚。
- `NoProperty`：去掉财产风险。
- `NoFatal`：去掉伤亡风险。

论文用途：消融表格，说明本文不是靠单一成本项工作。

### E5：算法效率与可扩展性

目的：证明方法在城市级网格上可运行。

测试网格：

- `40 x 40 x 12`
- `60 x 60 x 12`
- `80 x 80 x 12`
- `100 x 100 x 12`

记录：

- 运行时间。
- 扩展节点数。
- 峰值内存。
- 是否找到可行路径。
- 路径总代价。

如果后续实现 EDA + K-means corridor，应额外对比：

- `Cost-A* full grid`
- `EDA corridor + Cost-A*`

论文用途：可扩展性分析。

### E6：参数敏感性分析

目的：证明结果对关键参数不是偶然。

建议扫描：

- `k_w`：2、3、5。
- `gamma_rain`：0.001、0.005、0.01。
- `K_obs`：5、10、20。
- `sigma_decay`：200、300、500 m。
- `w_noise`：从 0 到 0.6。

输出：

- 路径总代价变化。
- 路径长度变化。
- 风险暴露变化。
- 路径空间偏移量。

论文用途：敏感性分析小节。

## 8. 基线方法定义

基线要简单、清楚、可解释。不要把基线做得比本文方法还复杂。

| 名称 | 使用成本 | 是否时间动态 | 用途 |
|---|---|---:|---|
| `Shortest-A*` | 距离/时间 + 硬避障 | 否 | 最基本对照 |
| `ConstantRisk-A*` | 距离 + 常数坠机风险后果 | 否 | 对照传统常数风险假设 |
| `StaticRisk-A*` | 距离 + 全天平均风险张量 | 否 | 对照静态风险地图 |
| `TimeRisk-A*` | 距离 + 动态伤亡/财产风险 | 是 | 检验动态安全风险贡献 |
| `FullRisk-A*` | 距离 + 动态风险 + 噪声 | 是 | 本文主要方法 |
| `EDA-Corridor + FullRisk-A*` | 全局引导 + 精确搜索 | 是 | 后续加速版本 |

如果时间有限，论文初稿至少完成前三个基线和 `FullRisk-A*`。

## 11. 论文图表产出清单

## 12. 推荐推进顺序

### 第一阶段：冻结公式与配置

目标：

- 明确 `lambda_base` 的单位是每小时。
- 明确微观场景使用 24 个小时切片，宏观场景使用 96 个 15 分钟切片。
- 明确 `cost_weight.yaml` 是当前权重配置文件，不必急着改名为 `weight_scenarios.yaml`。

验收标准：

- 配置文件能解释论文公式中的每个参数。
- 所有权重场景 `w_ops + w_fatal + w_prop + w_noise = 1`。

### 第二阶段：完成微观 mock 数据

目标：

- 构造可控建筑群。
- 构造土地利用区域。
- 构造 POI 和人口潮汐。
- 构造风雨风险热点。

验收标准：

- 能生成建筑高度图、土地利用图、风雨时间序列和人口密度热力图。
- 风险热点位置和时间是可解释的。

### 第三阶段：完成张量引擎

目标：

- 输出 `obstacle_mask`、`p_crash`、`fatal_cost`、`property_cost`、`noise_cost`。
- `tensor_builder` 按论文公式生成综合成本。

验收标准：

- 所有张量无 NaN。
- `p_crash` 在 `[0,1]`。
- `obstacle_mask` 能正确屏蔽建筑体素。
- 噪声成本白天/夜间敏感区符合 S-T 矩阵。

### 第四阶段：完成路径规划和基线

目标：

- 先完成可用的 Cost-A*。
- 先用完整网格搜索跑通论文主实验。
- EDA/K-means 走廊作为后续效率增强。

验收标准：

- 所有基线能在同一 OD、同一配置下输出路径。
- 每条路径能回算分项成本。
- 路径不穿越 `obstacle_mask`。

### 第五阶段：批量实验与论文图表

目标：

- 自动跑基线、时段对比、权重对比、消融、敏感性。
- 输出 `metrics.csv` 和论文图。

验收标准：

- `05_case_study.tex` 的每个实验结论都有对应图表或表格支撑。
- 每张图都能追溯到具体 `run_id` 和配置快照。

## 13. 常见陷阱

### 13.1 把噪声也乘以 `P_crash`

这是理论错误。噪声是正常飞行成本，不是事故后果。

### 13.2 把建筑障碍当成高成本

建筑体素应作为不可行节点剪枝。高成本不能保证绝对避障。

### 13.3 归一化方式破坏时空差异

不要每个时间片单独归一化，否则早高峰和夜间的绝对风险差异会被消掉。

### 13.4 只报告总成本

总成本是权重后的结果，无法说明机制。必须报告分项成本。

### 13.5 先追求真实数据，导致主线停滞

真实 OSM、WorldPop、ERA5 很重要，但论文机制可以先用 mock 城市场景验证。建议微观场景先合成，宏观场景再逐步替换真实数据。

### 13.6 `tensor_builder` 变成普通加法器

当前 `tensor_builder.py` 的加权求和只是工程雏形。论文需要的是公式感知组合：

```text
w_fatal * p_crash * fatal_cost
w_prop  * p_crash * property_cost
w_noise * noise_cost
```

### 13.7 时间推进与路径边不一致

A* 扩展边时，下一节点的时间索引应由当前累计飞行时间决定，而不是简单每走一步加一个固定小时。若每条边飞行时间小于时间片，可以保持在同一时间片，直到累计时间跨片。

## 14. `05_case_study.tex` 写作骨架

实验完成后，论文案例研究章节可以按这个结构写。

### 14.1 研究区域与数据准备

说明：

- 网格分辨率。
- 高度层。
- 时间步长。
- 建筑、人口、土地利用、气象数据来源。
- 如果使用 mock 数据，明确其目的是机制验证。

### 14.2 实验设置

说明：

- 无人机速度、最高/最低高度、安全裕度。
- 起终点设置。
- 权重场景。
- 基线方法。
- 评价指标。

### 14.3 结果与分析

重点回答：

- 本文方法相对最短路降低了多少风险？
- 代价是什么，是多走了多少距离或时间？
- 哪些区域被主动避开？
- 不同时段路径为什么不同？

### 14.4 消融实验

说明：

- 去掉动态 `P_crash` 后，路径是否穿过高风/高雨/城市峡谷区域？
- 去掉人口潮汐后，是否无法避开早晚高峰区域？
- 去掉 S-T 噪声矩阵后，是否无法体现夜间住宅区和白天学校医院保护？

### 14.5 可扩展性与敏感性

说明：

- 网格变大时运行时间如何增长。
- 关键参数变化是否改变结论。
- EDA/K-means corridor 如果实现，可在这里作为加速机制展示。
