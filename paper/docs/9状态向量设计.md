# 状态演化与时空寻优节点设计

## 1. 问题背景：传统单一代价值的局限性

在经典 A* 算法框架中，每个搜索节点通常仅维护一个标量代价值 $g(n)$（从起点到当前节点的累积距离或总代价）。然而，在本文提出的**动态多维 TPR 风险模型**中，直接使用单一标量 $g(n)$ 进行路径优化存在以下理论缺陷和工程瓶颈：

### 1.1 数学逻辑的割裂：加法与乘法的本质冲突

TPR 模型中的不同物理量具有不同的代数属性：

| 风险维度 | 累积方式 | 数学性质 | 说明 |
|---------|---------|---------|------|
| 飞行距离 $D$ | 累加（Additive） | $D_{total} = \sum d_i$ | 欧氏距离的线性叠加 |
| 噪音成本 $C_{noise}$ | 累加（Additive） | $C_{total} = \sum c_i \cdot \Delta t$ | 时间积分型代价 |
| 财产损失 $C_{property}$ | 累加（Additive） | $C_{total} = \sum c_i \cdot \Delta t$ | 期望损失的线性叠加 |
| **系统存活概率 $P_{survival}$** | **相乘（Multiplicative）** | **$P_{total} = \prod (1 - p_{crash,i})$** | **马尔可夫链属性，独立事件概率连乘** |

**核心矛盾**：若将 $P_{survival}$ 强行转化为某种"加法代价"混入 $g(n)$，在概率学上是不严谨的。例如：
- 错误做法：$g(n) = w_1 \cdot D + w_2 \cdot C_{noise} + w_3 \cdot (-\ln P_{survival})$
- 问题：虽然对数变换可将乘法转为加法，但丢失了概率的物理意义，且无法支持基于阈值的硬约束剪枝（如"存活率低于 99.9% 立即禁飞"）

### 1.2 多目标优化的可解释性缺失

当算法到达终点时，若仅保留加权后的标量 $g(n)$，将无法回答以下关键问题：
- "这条路径的预期致死人数是多少？"
- "噪音影响了多少居民？"
- "财产损失的经济成本具体为多少？"

**学术后果**：失去结果的可解释性，无法向审稿人展示各风险维度的独立贡献，违背了多目标透明化决策的研究初衷。

### 1.3 硬约束（Hard Constraints）的剪枝判定失效

真实工程场景中需要实施严格的"熔断机制"：
- **电池约束**：累计飞行时间超过电池极限 $\Rightarrow$ 强制终止搜索
- **安全约束**：系统存活概率跌破阈值（如 $P_{survival} < 0.999$）$\Rightarrow$ 拒绝该节点
- **法规约束**：闯入夜间极度敏感区（噪音惩罚 $> 10$）$\Rightarrow$ 立即剪枝

只有显式维护各维度的状态量，才能支持这种高精度的约束检查。

## 2. 状态向量设计方案

基于上述分析，本文提出**显式状态向量（Explicit State Vector）**架构，将不同代数属性的物理量分离存储，确保数学严谨性与工程可操作性。

### 2.1 状态向量的数据结构定义

```python
class SearchNode:
    """
    时空搜索节点：承载四维坐标、状态向量及A*寻优变量
    """
    def __init__(self, x, y, z, t, state_vector, parent=None):
        # 1. 时空坐标：绝对不可分离的4D定位
        self.coords = (x, y, z, t) 
        
        # 2. 状态向量字典：记录各维度的物理累积量
        self.state = {
            'cum_distance': state_vector.get('cum_distance', 0.0),      # 累计飞行距离 (m)
            'cum_time': state_vector.get('cum_time', 0.0),              # 累计飞行时间 (s) -> 决定电池消耗
            'p_survival': state_vector.get('p_survival', 1.0),          # 存活概率 (1.0表示100%存活) -> 乘法累积
            'cum_fatality': state_vector.get('cum_fatality', 0.0),      # 累计致命风险 (预期致死人数)
            'cum_property': state_vector.get('cum_property', 0.0),      # 累计财产损失成本 (货币单位)
            'cum_noise': state_vector.get('cum_noise', 0.0)             # 累计社会噪音滋扰代价
        }
        
        # 3. 算法寻优变量 (A* 必备)
        self.g = 0.0  # 起点到当前点的加权综合代价
        self.f = 0.0  # f = g + h (启发式总代价)
        
        # 4. 指针：用于回溯完整路径
        self.parent = parent
```

### 2.2 设计原则说明

1. **分离关注点**：状态向量 `state` 负责记录物理世界的真实演化，而 `g` 值仅作为算法优化的单目标代理
2. **轻量级实例化**：仅在搜索树中实际访问到的节点才会被实例化（典型场景下几千至几万个），而非为全图千万级网格预分配对象
3. **张量索引加速**：风险场数据存储在连续的 Numpy/Tensor 数组中，通过 `env_tensor.p_crash[x,y,z,t_idx]` 直接索引，避免对象查找开销

## 3. 状态转移方程：节点扩展的核心计算逻辑

本节描述算法从当前节点 $A(x_1, y_1, z_1, t_1)$ 探索相邻候选节点 $B(x_2, y_2, z_2)$ 时的完整状态更新流程。这是论文第三章算法部分的核心，也是代码实现的关键。

### 3.1 时间流逝计算（Time Progression）

$$\Delta t_{fly} = \frac{\sqrt{(x_2-x_1)^2 + (y_2-y_1)^2 + (z_2-z_1)^2}}{v_{UAV}}$$

$$t_2 = t_1 + \Delta t_{fly}$$

其中 $v_{UAV}$ 为无人机恒定巡航速度（单位：m/s）。

**离散化处理**：将连续时间 $t_2$ 映射到时间切片索引：
$$t_{idx} = \left\lfloor \frac{t_2}{\Delta t_{slice}} \right\rfloor$$

### 3.2 基于时空张量场的风险属性提取

利用预先构建的四维风险张量（Risk Tensor Field），直接索引获取节点 B 在时刻 $t_2$ 的各项物理风险：

```python
# 伪代码：张量索引（无需实例化Point对象）
p_crash_local   = env_tensor.p_crash[x2, y2, z2, t_idx]       # 动态坠机概率
fatality_local  = env_tensor.fatality[x2, y2, z2, t_idx]      # 结合人口潮汐的致死率
property_local  = env_tensor.property[x2, y2, z2]             # 静态/动态建筑财产风险
noise_local     = env_tensor.noise[x2, y2, z2, t_idx]         # 结合昼夜惩罚的噪音代价
```

**工程优势**：
- 利用 Numpy 的连续内存布局，索引操作为 $O(1)$ 复杂度
- 支持批量向量化计算（如同时评估多个邻居节点）
- 内存占用仅为原始数据的连续块（例如 $100 \times 100 \times 10 \times 30$ 的浮点数组约 12 MB）

### 3.3 状态向量的更新规则

#### （1）累加型状态的更新

对于距离、时间、期望损失等具有加法性质的量：

$$\text{cum\_distance}_{new} = \text{cum\_distance}_{old} + ||\vec{AB}||$$

$$\text{cum\_time}_{new} = \text{cum\_time}_{old} + \Delta t_{fly}$$

$$\text{cum\_fatality}_{new} = \text{cum\_fatality}_{old} + P_{survival}(t_1) \cdot \text{fatality\_local} \cdot \Delta t_{fly}$$

$$\text{cum\_property}_{new} = \text{cum\_property}_{old} + P_{survival}(t_1) \cdot \text{property\_local} \cdot \Delta t_{fly}$$

$$\text{cum\_noise}_{new} = \text{cum\_noise}_{old} + \text{noise\_local} \cdot \Delta t_{fly}$$

**关键洞察**：致死风险和财产损失的期望值需要乘以**当前存活概率** $P_{survival}(t_1)$，因为只有无人机未坠毁时才可能产生地面伤害。这体现了风险传导的条件概率特性。

#### （2）乘法型状态的更新（核心创新点）

系统存活概率遵循马尔可夫链的独立性假设，采用乘法累积：

$$P_{survival}(t_2) = P_{survival}(t_1) \times \left[1 - P_{crash}(x_2, y_2, z_2, t_2)\right]$$

**数学推导**：
- 设无人机在时刻 $t_1$ 的存活概率为 $P_{survival}(t_1)$
- 从 $t_1$ 到 $t_2$ 的飞行过程中，坠机概率为 $P_{crash}(x_2, y_2, z_2, t_2)$
- 根据条件概率公式：$P(\text{存活至}t_2) = P(\text{存活至}t_1) \cdot P(\text{不坠机}| \text{已存活至}t_1)$
- 由于马尔可夫性，$P(\text{不坠机}| \text{已存活至}t_1) = 1 - P_{crash}(x_2, y_2, z_2, t_2)$

**学术价值**：这一乘法更新规则在概率学上是严格正确的，区别于许多灌水论文中粗暴的对数变换或线性近似。

### 3.4 硬约束剪枝（Hard Constraints Pruning）

在生成新节点后，立即执行约束检查，不符合条件的节点直接丢弃（不加入 Open List）：

```python
# 约束1：存活概率阈值（安全熔断）
if new_state['p_survival'] < params.survival_threshold:  # 例如 0.999
    return None  # 拒绝该节点

# 约束2：电池续航极限
if new_state['cum_time'] > params.max_battery_time:  # 例如 1800秒 (30分钟)
    return None  # 电池耗尽，拒绝

# 约束3：噪音法规上限（可选）
if noise_local > params.noise_regulation_limit:  # 例如夜间敏感区惩罚>10
    return None  # 违反法规，拒绝
```

### 3.5 综合代价值 $g(n)$ 的计算

最终，将状态向量中的各维度风险按照权重聚合为单目标优化函数：

$$g(S_j) = w_1 \cdot \text{cum\_fatality}_j + w_2 \cdot \text{cum\_property}_j + w_3 \cdot \text{cum\_noise}_j$$

其中权重系数 $w_1, w_2, w_3$ 由决策者根据政策偏好设定（例如生命安全优先则 $w_1 \gg w_2, w_3$）。

**注意**：$g(n)$ 仅用于 A* 算法的优先级队列排序，真正的物理量仍保存在 `state` 字典中供后续分析。

## 4. 完整算法流程伪代码

```python
def expand_node(current_node, neighbor_coords, env_tensor, params):
    """
    节点扩展函数：从当前节点探索邻居节点，返回新的SearchNode或None
    
    参数:
        current_node: 当前SearchNode对象
        neighbor_coords: 邻居节点的空间坐标 (x2, y2, z2)
        env_tensor: 四维风险张量场（包含p_crash, fatality, property, noise等字段）
        params: 算法超参数配置对象
    
    返回:
        neighbor_node: 新生成的SearchNode对象，若不满足约束则返回None
    """
    # --- 步骤1: 解析当前状态 ---
    x1, y1, z1, t1 = current_node.coords
    x2, y2, z2 = neighbor_coords
    
    # --- 步骤2: 计算时间流逝 ---
    dist = euclidean_distance((x1, y1, z1), (x2, y2, z2))
    dt = dist / params.uav_speed
    t2 = t1 + dt
    
    # 获取离散化时间索引
    t_idx = int(t2 / params.time_resolution)
    
    # --- 步骤3: 基于时空张量场提取风险属性 ---
    p_crash_local = env_tensor.p_crash[x2, y2, z2, t_idx]
    fatality_local = env_tensor.fatality[x2, y2, z2, t_idx]
    property_local = env_tensor.property[x2, y2, z2]
    noise_local = env_tensor.noise[x2, y2, z2, t_idx]
    
    # --- 步骤4: 更新状态向量 ---
    new_state = {}
    new_state['cum_distance'] = current_node.state['cum_distance'] + dist
    new_state['cum_time'] = current_node.state['cum_time'] + dt
    
    # 【核心】存活概率的乘法更新
    new_state['p_survival'] = current_node.state['p_survival'] * (1 - p_crash_local)
    
    # 期望风险的累加（需乘以当前存活概率）
    new_state['cum_fatality'] = current_node.state['cum_fatality'] + \
                                (current_node.state['p_survival'] * fatality_local * dt)
    new_state['cum_property'] = current_node.state['cum_property'] + \
                                (current_node.state['p_survival'] * property_local * dt)
    new_state['cum_noise'] = current_node.state['cum_noise'] + (noise_local * dt)
    
    # --- 步骤5: 硬约束剪枝 ---
    if new_state['p_survival'] < params.survival_threshold:
        return None
    if new_state['cum_time'] > params.max_battery_time:
        return None
    
    # --- 步骤6: 计算综合代价值 g(n) ---
    g_new = (params.w1 * new_state['cum_fatality'] + 
             params.w2 * new_state['cum_property'] + 
             params.w3 * new_state['cum_noise'])
    
    # --- 步骤7: 创建新节点 ---
    neighbor_node = SearchNode(x2, y2, z2, t2, new_state, current_node)
    neighbor_node.g = g_new
    neighbor_node.h = heuristic_estimate((x2, y2, z2), goal_coords)  # 启发式函数
    neighbor_node.f = neighbor_node.g + neighbor_node.h
    
    return neighbor_node
```

## 5. 内存管理策略：为何不会溢出？

### 5.1 传统误区：为每个网格预分配对象

**错误做法**：
```python
# ❌ 灾难性设计：为1000万网格各创建一个Point对象
grid_map = {}
for x in range(100):
    for y in range(100):
        for z in range(10):
            grid_map[(x,y,z)] = Point(x, y, z)  # 内存爆炸！
```

**问题分析**：
- Python 对象的内存开销极大（每个对象约 200-400 字节）
- $10^7$ 个对象 $\approx$ 2-4 GB 内存，且访问速度慢（哈希表查找）

**本文方案**：

**内存对比**：
| 方案 | 内存占用 | 访问速度 | 可扩展性 |
|------|---------|---------|---------|
| 预分配对象 | 2-4 GB | 慢（哈希查找） | 差 |

**学术表述建议**：
> 本研究采用**混合内存管理策略**：静态风险场数据存储于连续的 Numpy 多维数组中，利用其缓存友好性和向量化计算优势；动态搜索树中的节点仅在 CostA* 算法实际探索时按需实例化。该设计将内存占用从传统对象预分配方案的 GB 级降至 MB 级，同时保证了 $O(1)$ 复杂度的风险查询效率。

## 6. 学术论文表述建议

以下段落可直接用于论文**第五章：路径规划算法**中的"状态演化与节点设计"小节：

> ### 5.4 状态演化与时空寻优节点设计 (State Evolution and Spatiotemporal Node Design)
> 
> 为克服传统 A* 算法中单一标量代价值 $g(n)$ 在多目标动态环境下的理论局限，本文提出**显式状态向量（Explicit State Vector）**架构。该设计将具有不同代数属性的物理量分离存储，确保数学严谨性与工程可操作性。
> 
> **状态向量定义**：每个搜索节点 $S = (x, y, z, t)$ 维护一个六维状态向量 $\mathbf{V} = [D, T, P_{surv}, R_{fat}, C_{prop}, C_{noise}]^T$，分别表示累计飞行距离、累计飞行时间、系统存活概率、累计致命风险、累计财产损失及累计噪音代价。
> 
> **乘法型状态更新**：系统存活概率 $P_{survival}$ 遵循马尔可夫链的独立性假设，采用乘法累积规则：
> $$P_{survival}(t_{j}) = P_{survival}(t_{i}) \times \left[1 - P_{crash}(x_j, y_j, z_j, t_j)\right] \tag{5.3}$$
> 其中 $P_{crash}(\cdot)$ 由第四章的气象-机械耦合模型给出。该更新规则在概率学上严格正确，区别于文献中常见的对数变换或线性近似方法。
> 
> **加法型状态更新**：对于期望损失类指标（致死风险、财产损失），其更新需考虑条件概率特性：
> $$R_{fat}(t_j) = R_{fat}(t_i) + P_{survival}(t_i) \cdot \rho_{fatality}(x_j, y_j, z_j, t_j) \cdot \Delta t_{fly} \tag{5.4}$$
> 物理意义为：只有无人机未坠毁时（概率为 $P_{survival}(t_i)$），才可能对地面人员造成伤害。
> 
> **硬约束剪枝机制**：在节点扩展后立即执行约束检查，包括：
> - 安全约束：$P_{survival} < \theta_{safe}$（例如 0.999）时触发熔断，拒绝该节点；
> - 能源约束：累计飞行时间超过电池极限 $T_{max}$ 时终止搜索；
> - 法规约束：局部噪音代价超过监管上限时强制规避。
> 
> **内存优化策略**：本研究采用**混合内存管理架构**——静态风险场存储于连续的 Numpy 多维数组（占用 < 50 MB），动态搜索节点仅在 CostA* 实际探索时按需实例化（典型场景下 < 10,000 个节点）。该设计将内存占用从传统对象预分配方案的 GB 级降至 MB 级，同时保证了 $O(1)$ 复杂度的风险查询效率。

## 8. 关键参数调优指南

| 参数符号 | 物理含义 | 推荐范围 | 敏感性分析 |
|---------|---------|---------|-----------|
| $\theta_{safe}$ | 存活概率阈值 | 0.99 - 0.999 | 越高则路径越保守，绕行距离增加 |
| $T_{max}$ | 电池续航极限 | 1200 - 3600 s | 直接影响可达区域半径 |
| $\Delta t_{slice}$ | 时间切片分辨率 | 30 - 300 s | 越小精度越高，但张量内存线性增长 |
| $w_1, w_2, w_3$ | 多目标权重 | 归一化后总和为1 | 需通过敏感性实验确定最优配比 |
| $v_{UAV}$ | 巡航速度 | 5 - 15 m/s | 影响时间流逝速率及风险暴露时长 |
